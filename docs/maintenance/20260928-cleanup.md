  brokerage-preview and research entry points.

  older service infrastructure versus the document-pilot architecture.

  production portal Dockerfile-specific allowlists are unchanged.
- Added a dry-run-first cache cleaner. It inspects known cache file shapes, refuses
  symlinks, unexpected content and Git-tracked files, and never recursively
  deletes a directory. It does not cross nested Git repositories or touch
  `tmp/`, `private/`, outputs, dependencies, builds or provider state.
- Removed eight previously Git-tracked CPython 3.13 bytecode files after checking
  that each was unchanged relative to the index and had its Python source present.
  This was a bounded one-time removal; the general cleaner still refuses tracked
  files. No index changes or commits were made.

## What remains intentionally

The `tmp/` directory contains the recorded website production artifact,
immediate rollback, unapproved conversion candidate and older regression inputs.
They stay at their existing paths. Dated source layers, QA/research evidence,
dependencies, migrations and older services still have references; none has been
declared dead merely because it is old.

The working tree already contained extensive uncommitted/untracked changes.
This cleanup does not commit, reset, discard or deploy those changes. A fresh
Git clone is not a backup of this local workspace. Before larger source or
snapshot removals, establish a reviewed, secret-free source/release backup and
migrate the dependent regression manifests in a separate change.
